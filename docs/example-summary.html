Decisions made

DecisionWhy
Route on output type, not vocabulary"eli5 summary" matched two skills when eli5 was only a modifier
Modes live in separate filesThe default stays cheap to load
Both page skills share one specTwo skills drifting apart would produce two house styles
Gather before writingSummarising from memory is where invented status comes from
No animation libraryA CDN link breaks the one-file rule and dies offline

Open

  • Routing is fuzzy description matching, not a hard rule. The case to watch is "eli5 summary of this branch", which should return a file.
  • Accessible is a mode, not the default. Undecided whether it should be the other way round, with a plain opt-out.
  • Skill paths shift between agent versions. The README hedges rather than promising a path.
